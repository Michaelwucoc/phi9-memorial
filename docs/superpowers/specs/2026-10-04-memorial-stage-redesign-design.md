# Phi9 Memorial 全站舞台式重设计

## 目标

将 Phi9 Memorial 从分区卡片式长页升级为统一的固定舞台叙事体验：滚轮推进内容状态，界面以克制、紧凑、专业的视觉层级呈现真实档案；解谜过程不嵌入解谜截图，而以字符、表格、分析图形和排布动效复现；音乐区支持把曲目归档到收藏槽并从收藏槽取出播放；频谱基于当前音乐的真实音频样本渲染。

## 设计原则

- 视觉参考：主人确认以当前解谜固定舞台作为全站交互语言的基准，不引入未经确认的外部设计引用。
- 只呈现可核实的资料和术语，避免虚构倒计时结果、群体角色、动机旁白或自动操作文案。
- 固定镜头只应用于适合叙事的章节场景；曲目档案、收藏品检索等大量内容仍需提供可读、可键盘操作的方式，避免强迫所有内容成为全屏动画。
- 滚动驱动是渐进增强：减少动态效果偏好、触屏、键盘导航、窄视口及 `file://` 打开时必须仍可使用。
- 所有重要操作必须有拖拽之外的按钮/键盘替代方式。
- 频谱以真实数据为准；不能分析音频时优先保证声音，关闭频谱而不是回退到假动画。

## 受众与体验定位

- 受众：Phigros 第九章玩家、解谜参与者和纪念站访客。
- 情绪：克制、肃穆、恢宏；靠真实线索的尺度、留白、显影次序与章节过渡制造张力，而非用炫光、卡片堆叠或夸张文案。
- 信息密度：舞台中等偏低；一屏只突出一个阶段或一个主要动作。资料列表可滚动、搜索、下载。
- 色彩：沿用现有深蓝黑、低亮蓝与冷白体系，重要解谜结果才获得更高亮度。
- 文案：简短档案标签与经核实的内容，不写面向玩家的 AI 式指令。

## 范围

### 包含

1. **全站统一舞台语言**
   - 将 Hero、解谜、图像/收藏档案、音乐、音效、致谢设计为有层次的章节体验。
   - 采用固定/吸附舞台与滚动进度驱动显影；大规模档案仍提供常规滚动/检索，避免把可检索数据锁入动画。
   - 章节之间应明确交接，滚动离开舞台后恢复自然文档流，不产生嵌套滚动陷阱。

2. **解谜过程重构**
   - 移除解谜叙事舞台中的所有嵌入式截图。
   - 第一阶段细化成图像/源码线索 → 傅里叶变换 → 频域结果 `Outside_the_birdcage` 的文字和可解释图形显影；不可伪称重算了 FFT，除非确实使用可验证输入实时计算。初期可用来源文本给定的结果，动画仅表达逐步读取过程。
   - 第二阶段 `Outside_the_birdcage` 保持更长滚动区间；结果字符散开/分组/归位，过渡为 13 段碎片的文字矩阵。按整理稿展现 `DISPOSSESSION` 末尾字母排序、`IGNORANCE` / `DISPOSSESSION` 标记、黄色格顺时针读出 `Cogito, ubi sit refugium`。
   - 后续文本步骤依社区整理稿：零宽字符 → Morse → `DISORIENTATION`；Nihilist 运算 → `JUSTENGAGEWTH`；Fence / zigzag → `NOL2re@etiKdA3!ig9t~UmSO`。
   - 提供简洁阶段索引；scroll 与进度映射单调、可逆，可往回滚。

3. **音乐归档交互**
   - 曲目可通过桌面拖入收藏槽，呈现曲目被收纳/归档的转场；从收藏槽拖出，或用点击/键盘控制取出并播放。
   - 触屏设备使用明确的“收纳/取出”动作，不要求拖拽。
   - 收藏状态当前仅保存在本地浏览器；不得暗示账号同步或跨设备共享。
   - 现有单曲下载、WAV/AAC 批量下载、曲绘/音效下载仍可达。

4. **真实实时音频频谱**
   - 在用户主动播放后分析正在播放的 `<audio>`，频谱数据由 `AnalyserNode.getByteFrequencyData()` 或经测试的真实采样获得。
   - 推荐实现：在用户手势触发时创建/恢复 `AudioContext`，建立 `MediaElementSource → AnalyserNode → destination`，频谱使用 analyser bin；保持单一 source 连接，切曲不重复连线。
   - 音频跨域/CORS 或 `file://` 约束风险：先用测试验证当前浏览器与文件方式。若不能安全分析，必须不接管音频并原生直连播放；可在 UI 隐去频谱，不允许假波形。
   - 播放/暂停/切曲/错误/结束时正确启动或停止绘制与资源；绘制只在有可见播放器且播放中运行。

### 不包含

- 不添加未在来源中出现的解谜剧情、阶段结论、解谜者身份归因或虚构统计。
- 不重写/再压缩站内原曲绘、剧情图片、音乐、SFX、ZIP 文件。
- 不更换品牌名、站点地址、数据内容与现有版权说明。
- 不加入外部运行时依赖或网络字体；站点仍本地静态可运行。

## 数据事实与出处

- 解谜链的依据：仓库根目录 `第九章解谜全过程.pdf` 与 `NOTES.md` “最终链”段落。
- 确认顺序：源码图 → FFT 得 `Outside_the_birdcage` → 收齐 13 段并排序 → 黄色格顺时针读 `Cogito, ubi sit refugium` → 零宽/Morse 得 `DISORIENTATION` → Nihilist 得 `JUSTENGAGEWTH` → 栅栏之字形读得 `NOL2re@etiKdA3!ig9t~UmSO`。
- 解释性动画应准确区分“真实算法计算”与“对既有解谜结果的演示”。

## 交互与可访问性

- 滚动：舞台章节有明确开始与结束；进入后固定构图，滚动渐进切换；离开后自然继续页面。浏览器后退/前进、锚点链接与顶部导航保留。
- 键盘：可聚焦曲目行/收藏槽；提供 Enter/Space 收纳或播放、方向键在收藏项目间移动；焦点状态明显。
- 拖拽：使用 Pointer Events 处理鼠标/触屏时要区分页面纵向滚动与横向拖动；不得劫持普通滚轮或触摸垂直滚动。
- 减少动态效果：使用 `prefers-reduced-motion` 时禁用舞台转场/长位移，改为直接切换或普通文档式内容。
- 语义：阶段标题、进度和播放器状态有可读文本与适当 ARIA；装饰性 Canvas/SVG 隐藏于辅助技术。

## 技术实现边界

现有静态结构：`Phi9-Memorial/index.html`、`assets/css/style.css`、`assets/js/main.js`，数据脚本 `assets/js/data-*.js`。不引入 bundler、框架或服务端。

推荐在 `assets/js/` 下将新增逻辑拆成独立脚本（例如 `decrypt-stage.js`、`archive-drag.js`、`audio-visualizer.js`），由 HTML 按依赖顺序加载；如沿用 main.js 内 IIFE，应将各模块职责隔离并写清初始化入口。CSS 使用章节/舞台命名空间，防止全站 `.sec/.page` 通用规则覆盖舞台定位。

## 状态与失败处理

- 舞台未激活/已离开：停止高频渲染；保持当前滚动位置，不锁住页面。
- JavaScript 关闭/失败：核心文本与资源仍以普通 DOM 文档可见，不能只有空舞台。
- 收藏槽为空：提供真实空状态，不造假曲目；收藏写入失败时退化为页面内会话态。
- 拖拽取消：原曲目保留原位；不可重复收纳同一曲目。
- 音频分析不可用：取消 AudioContext 接管，保留原生音频链，播放器继续工作，频谱元素隐藏。
- 自动播放拒绝：显示/保留可点击播放入口，不连续重试。

## 性能约束

- 不在每个滚动事件执行布局读写；使用一个 requestAnimationFrame 合并更新，必要时 IntersectionObserver。
- 音频 canvas 分辨率受 devicePixelRatio 上限约束；仅播放时、可见时采样；停止/关闭时取消 RAF。
- 页面核心资源不依赖 CDN。
- 保留图片/音频 lazy loading 策略，避免所有大图与音轨同时解码。

## 验收标准

1. 资源顺序仍为解谜优先，之后是图像、收藏、音乐、音效、致谢。
2. 解谜舞台中 0 个 `<img>`，所有阶段均由文本/DOM 图形呈现；原档下载区仍保留真实图片。
3. 解谜 scroll progress 在上下滚动时可逆更新；首幕展现 FFT 概念与已知输出，不冒称实时分析原图；第二幕持续区间明显长于一般步骤，并衔接到 13 行碎片表。
4. 桌面和移动设备均可浏览解谜、到达后续章节，舞台没有永久遮挡或页面滚动锁死。
5. 曲目可拖放收藏与取出；触屏、键盘和纯点击路径都可完成等价动作；状态正确且下载链接不变。
6. 播放音乐时频谱数值来自当前音频 analyser 数据，不由时间/随机数合成；暂停时静止/清空。
7. file:// 与 HTTP 本地服务都测试音频：无法分析时仍能正常听到声音，且不显示假频谱。
8. `prefers-reduced-motion` 下可完成导航和播放，不依赖长动画。
9. 浏览器无新增 JS 异常；核心档案素材路径无 404；静态页面无需构建即可打开。

## 实施顺序建议

此改造包含三个可独立验证的子系统，应分为三个实施计划/可交付步骤：

1. 解谜固定舞台与逐步演算重构（文字化、FFT/13 段表过渡）。
2. 音乐收藏槽及收纳/取出演示交互。
3. 实时音频频谱与原生音频安全回退。

三部分共用视觉 tokens，但测试和故障边界分开，避免把音频回退问题与页面滚动/拖拽问题耦合。
